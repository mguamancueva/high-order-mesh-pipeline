# Case Study 2: Overcoming Export Limitations (Elevation to Order 4)

## 📌 The Problem: The CGNS Format Bottleneck
During the pipeline development, a critical limitation was identified: exporting meshes with a geometric order higher than 2 from ANSA in `.cgns` format caused error loops in PyHOPE. The lack of standardization in the internal numbering of so many concurrent points in the CGNS format prevented the pre-processor from interpreting the spatial matrix, causing the execution to collaps.

## 🛠️ The Solution: Topological Injection with the Gmsh API
To break this barrier and achieve an Order 4 mesh, I developed a bridge script in Python using the Gmsh API. The strategy consists of separating the topology creation from the mathematical curving process:

1. **Base Reading:** The flat mesh (Order 2) in `.cgns` format generated by ANSA is imported.
2. **Entity Reconstruction:** Physical Groups (Sphere, Inlet, Outlet, etc.) are reassigned to maintain the original boundary conditions (PIDs).
3. **Topological Elevation (`setOrder(4)`):** Gmsh injects the necessary nodes into faces and edges to elevate the element to Order 4 mathematically, while leaving them geometrically flat. 
4. **Format Translation:** The mesh is exported in `.msh` format (native to Gmsh), which PyHOPE is capable of reading without crashing at high orders.

## ⚙️ Pre-processor Configuration (PyHOPE)
With the Order 4 topology built, the PyHOPE initialization file (`parameter.ini`) is configured to assimilate this new format:

* `FileName = ESFERA_HEXAS_g4_topo.msh`: Transitioning from the CGNS to the MSH format.
* `NGeo = 4`: Explicitly indicating the new geometric order.

**Result:** An Order 4 mesh ready and validated to be ingested by the HORSES3D spectral element solver.
